# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A Windows Electron app wrapping `music.youtube.com`. It includes global shortcuts (play/pause, next, previous), the Better Lyrics extension, and Discord "Listening to" activity. User-facing text is translated (English base, Korean) through `src/i18n.js`; never hardcode UI strings. Console logs are English only. This is a git repository (remote: `ddoiy13/certy-music`). Designs and plans live in `docs/superpowers/specs/` and `docs/superpowers/plans/`.

## Commands

- `npm start`: run in development
- `npm test`: `node --test test/*.test.js`. For a single file: `node --test test/settings.test.js`
- `npm run dist`: build the NSIS installer (`dist/CertyMusic-Setup.exe` + `.blockmap` + `latest.yml`). It runs with `--publish never`; nothing is uploaded.
- To try a different electron-builder config without touching `package.json` or `dist/`, write the whole `build` object to a temp JSON and run `npx electron-builder --win nsis --publish never --config <file>` with `directories.output` pointing elsewhere. `--config.publish.*` flags merge into the existing `publish` array and fail schema validation.
- Debugging: start with `YTM_DEBUG_PORT=9222 npm start` (ignored in packaged builds), then evaluate JS in the running page with `node scripts/cdp.js "<JS expression>"`. `node scripts/cdp.js --targets` prints the list of targets.
- `scripts/cdp.js` can't see HttpOnly cookies. For cookie checks, call CDP `Network.getAllCookies` over the same WebSocket (print names/lengths only, never values). Dev runs use a separate profile, so you must log in first.
- `scripts/cdp.js` only attaches to the `music.youtube.com` page. For the extension options page (`chrome-extension://<id>/options/index.html`, listed by `--targets`), write a small CDP script that attaches to that target and listens for `Runtime.exceptionThrown`.
- If `npm start` exits at once with code 0 and no error, a previous dev instance still holds the single-instance lock. Close any `electron.exe` running from this folder and restart. Editing `main.js` also needs a restart to take effect.
- `scripts/cdp.js` runs in the page's main world, so it cannot reach `preload.js` (isolated world), and synthetic events fail the `isTrusted` checks. Verify settings-tab changes by reading the DOM (e.g. `#app-settings-panel`) after the user clicks.

## Structure

- `src/main.js`: window creation, global shortcut registration, IPC handlers, external link guard. The logic is split out into pure modules.
  - `settings.js`: loads/saves `userData/settings.json` and validates shortcuts, window bounds, and the `discord` toggle (default on). A corrupted file is recovered with defaults.
  - `shortcuts.js`: wrapper around `globalShortcut`. Media keys are fixed; only user-defined shortcuts can be changed.
  - `player.js`: controls playback by clicking player bar buttons via `executeJavaScript`. All YouTube Music DOM selectors are kept in one place, `SELECTORS`.
  - `presence.js`: Discord Rich Presence via `@xhayper/discord-rpc`. `main.js` polls `player.readTrack` every 3 seconds and sends the track as a "Listening" activity. When paused, the activity stays but drops the timestamps (Discord cannot freeze its progress bar) and adds a `paused` small image; that asset must be uploaded under that name in the Discord application's Rich Presence Art Assets. Activity text is not translated. It does not affect the app when Discord is closed and reconnects every 15 seconds. `buildActivity` and `sameActivity` are pure functions; the client is injectable for tests. The toggle lives in the app settings tab (`settings:setDiscord`). `CLIENT_ID` is a Discord application ID, which is not a secret.
  - `extension.js`: loads `extensions/better-lyrics/` into the same session and opens its options window.
  - `updater.js`: wrapper around `electron-updater` for GitHub Releases updates. `createUpdater` takes an injectable `autoUpdater` (null in development runs, so nothing is checked) and keeps a status object (`idle/checking/available/downloading/ready/uptodate/error` plus `downgrade`). `main.js` checks 10 seconds after start and every 6 hours, pushes `update:state` to the settings tab, and shows a notification once per version (never for downgrades). The settings tab has the "빌드 버전" (Stable / Pre-Release) select and the auto-update toggle (`settings:setUpdateChannel`, `settings:setAutoUpdate`). Auto-update is off by default and installs on quit; the install button downloads and restarts immediately. **Downgrades are always manual**, even with auto-update on: `autoDownload` stays `false` and `updater.js` downloads only upgrades itself.
- `i18n.js` + `locales/{en,ko}.js`: UI text (English is the base; missing keys fall back to it). The `language` setting is `auto | en | ko`; `auto` follows `app.getLocale()` and falls back to English when undetected or unsupported. Errors cross IPC as translation keys (`reason: 'error.*'`, updater `error`), and the settings tab translates them. The sandboxed preload cannot `require` local files, so `main.js` sends the string table over `i18n:get`. To add a language, add `locales/<code>.js` and register it in `DICTS`; `test/i18n.test.js` checks key and placeholder parity.
- `src/preload.js`: injects an "앱 설정" (App Settings) tab into the YouTube Music settings screen. It manipulates the DOM directly in the isolated world and does not use `contextBridge`. Selectors for the settings screen are kept in the `SEL` object.
- `test/`: tests only the pure modules (`settings`, `shortcuts`, `player`, `presence`, `updater`). `main.js` and `preload.js` are verified by running the app.

## Constraints to Follow

- **Session**: the window and the extension both use the `persist:ytmusic` partition. Any new window must use the same session so that login and the extension are shared.
- **IPC trust**: `trusted()` in `main.js` only allows IPC coming from the main frame of `music.youtube.com`. Any new handler must also go through this check.
- **Navigation guard**: applied to every webContents in `web-contents-created`. `https` links outside YouTube/Google are sent to `shell.openExternal`; all other protocols are blocked.
- **Trusted Types**: `innerHTML` cannot be used on YouTube pages. `preload.js` uses only `createElement`, `textContent`, and `element.style`.
- **User-Agent**: keep the default. Removing the `Electron` token blocks Google login.
- **Login redirect**: when a logged-out session is redirected to `/premium` or `/musicpremium`, `will-redirect` sends it to the Google login URL exactly once. The `loginRedirected` flag prevents an infinite loop.
- **Cookie encryption**: packaged builds enable the `enableCookieEncryption` fuse. Development runs use a separate `userData` directory, `yt-music-electron-dev`, because an electron binary without the fuse corrupts the packaged app's cookie store if it touches it. Do not remove this separation code. After Google sign-out, `.google.co.kr` auth cookies (SID, HSID, etc.) stay on disk but the server treats them as signed out (verified once by a GET to google.co.kr; not proven for every endpoint). The fuse uses Windows DPAPI, so it protects against other Windows accounts and copied files, not malware running as the same user. Storage-side hardening beyond this has little value. Chrome's DBSC (device-bound cookies) shipped in Chrome 146 on Windows, but Electron support is unverified.
- **Privacy policy**: `PRIVACY.md` (linked from the README) lists every outbound data flow. Update it whenever you add or change one: Discord presence fields, updater requests, a new network call in `src/`, or a Better Lyrics replacement. Verified at 2026-10-23: `src/` has no `fetch`/`net.request`/analytics code. The only outbound paths are YouTube/Google, Discord (local IPC), and GitHub Releases. The bundled Better Lyrics extension contacts LRCLIB, betterlyrics.org (Unison), `lyrics.api.dacubeking.com`, and Google Translate. Its manifest has only `storage`/`alarms` permissions and a `music.youtube.com` host permission (no `chrome.cookies`). The exact request fields it sends are unverified.
- **Extension**: `extensions/better-lyrics/` is a bundled copy of the official Chrome build (3.0.0), patched for Electron. It has no auto-update and is packaged outside the asar via `extraResources`. Some behavior needs to be verified empirically in Electron (e.g., the MV3 service worker). The only local changes are for `electron-shim.js`, which fills in `chrome.*` APIs missing in Electron: the shim file itself, a content script entry at the top of `manifest.json`, an `import` on the first line of `background/service_worker.js`, and a `<script>` tag right after `<head>` in the 6 HTML pages (`action`, `options`, `pages/*`). To replace the extension, swap in the new official build, then run `node scripts/apply-better-lyrics-shim.js` (idempotent; re-applies all of these). Edit the shim at `scripts/better-lyrics/electron-shim.js`, not in the extension folder, or the next replacement loses the edit. A `chrome.*` API missing in Electron throws inside the options page's `DOMContentLoaded` handler and silently stops setup (symptom: tabs dead, switches still work, as with `chrome.extension.getViews`), so after replacing, check the options page for exceptions and add stubs to the shim. Better Lyrics settings live in the `persist:ytmusic` extension storage under `userData` and survive app updates; the extension ID is fixed by the manifest `key`. Whether a new Better Lyrics major version migrates old settings is unverified (3.0.0 was only tested on an empty dev profile).
- **Release procedure**: bump `version` in `package.json` → commit → push a tag `v<version>` (e.g. `git tag v1.2.0-beta.1 && git push origin v1.2.0-beta.1`). `.github/workflows/release.yml` then runs on `windows-latest`: it fails if the tag does not match `package.json` version, runs `npm test` and `npm run dist`, and creates the GitHub Release with `CertyMusic-Setup.exe`, its `.blockmap`, and `latest.yml` attached. A tag containing `-` is marked "Pre-release" automatically (use a version like `1.2.0-beta.1`, which is lower than `1.2.0`). The tag must be valid semver. To build locally without releasing, use `npm run dist`. The build writes `latest.yml` even for pre-release versions (verified with electron-builder 26.15.3). The Pre-Release setting only toggles `allowPrerelease`; do not set `autoUpdater.channel` (it forces `allowDowngrade` and breaks pre-release selection in `GitHubProvider`) and do not set `build.publish.channel` (it is baked into `app-update.yml` as the installed app's default channel, so switching to Stable would look for `beta.yml` in the stable release). Never build with `--publish always`; the build always runs with `--publish never` and the workflow uploads the artifacts with `gh release create`. The packaged installer is not code-signed, so integrity relies only on the hash in `latest.yml`.
