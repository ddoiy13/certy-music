# 작업표시줄 미리보기 버튼 설계

## 의도

작업표시줄 아이콘에 마우스를 올렸을 때 뜨는 창 미리보기에서, 창을 열지 않고 이전 곡, 재생/일시정지, 다음 곡을 조작한다.

## 목표와 비목표

- 목표: 버튼 3개(이전, 재생/일시정지, 다음). 가운데 아이콘은 재생 중이면 일시정지, 아니면 재생이다.
- 비목표: 설정 항목, 좋아요/셔플/반복 버튼, 미리보기 화면 꾸미기.
- 실패로 보는 경우: 아이콘이 실제 재생 상태와 어긋난 채로 남는다. 버튼이 사라진 채 돌아오지 않는다.

## 제약

- Electron `BrowserWindow.setThumbarButtons`를 쓴다. Windows 전용 앱이라 다른 OS는 고려하지 않는다.
- 버튼 동작은 `main.js`의 `handlers`(트레이, 전역 단축키와 같은 경로)를 재사용한다.
- 툴팁은 번역 문구를 쓰고, 언어를 바꾸면 함께 바뀐다.
- 새로 외부로 보내는 데이터가 없어 `PRIVACY.md`는 바꾸지 않는다.

## 접근 방식

- **A. 상태에 따라 아이콘 전환 (선택함)**: 지금 상태가 아이콘에 보인다. 상태 추적이 필요하다.
- B. 아이콘 고정: 더 단순하지만 아이콘만으로 상태를 알 수 없다.

## 설계 (작성자 판단)

- `src/thumbar.js`를 새로 만든다. 상태와 번역 함수로 버튼 목록을 만드는 부분은 순수 함수로 두고 `test/thumbar.test.js`에서 테스트한다.
- 상태는 `webContents`의 `media-started-playing`, `media-paused` 이벤트로 받는다. 시작할 때는 일시정지 상태로 본다.
- 언어가 바뀔 때와 창이 다시 보일 때(`show`) 버튼을 다시 설정한다. 창을 새로 만든 경우에도 다시 붙인다.
- 번역 키는 `tray.playPause`, `tray.prev`, `tray.next`를 재사용한다. `test/i18n.test.js`의 검사 파일 목록에 `thumbar.js`를 추가한다.
- 아이콘은 이미지 파일을 추가하지 않고 코드에서 비트맵으로 만든다. `build.files`에서 빠져 패키지에서만 아이콘이 비는 문제가 생기지 않는다.
- `CLAUDE.md`의 Structure 항목에 새 모듈을 적는다.

## 실행해서 확인할 것 (미확인)

- 두 이벤트가 YouTube Music의 재생, 일시정지, 곡 전환, 광고에서 실제 상태와 맞는가. 맞지 않으면 3초 간격으로 `player.readTrack`의 `playing`을 읽는 방식으로 바꾼다.
- 트레이로 숨겼다 다시 열어도 버튼이 남는가.
- 밝은 테마와 어두운 테마에서 아이콘이 보이는가. 안 보이면 테마에 따라 색을 바꾼다.
- 설치된 패키지에서도 버튼이 보이고 동작하는가.
